Ilustración del concepto, no una medición

Cada sesión empieza de cero

Sin un mapa, Claude Code lee archivo por archivo para entender tu proyecto. Eso gasta tokens y tiempo en cada pregunta.

Graphify + tu CLAUDE.md

Dos piezas que trabajan juntas.

Se activa solo

Vive en el CLAUDE.md del proyecto y se lee al iniciar sesión. No hay que pegarlo.

El grafo reemplaza el grep

Claude consulta el grafo en vez de leer archivos crudos uno por uno.

Sin capa extra de skill

El protocolo de output (modo Surgeon) queda por defecto, sin invocar nada cada vez.

Para no vender humo: el CLAUDE.md sí entra al contexto, no es gratis. Lo real es que se carga solo y, con el caché de prompt, su costo entre mensajes es casi insignificante.

Necesito que instales Graphify en este proyecto. Sigue estos pasos en orden y salta
cualquier paso cuyo requisito ya esté cumplido — no reinstales nada que ya exista:

1. Verifica si `uv` está instalado (`uv --version`). Si ya está, no lo reinstales,
   pasa directo al punto 2. Si no está, instálalo con:
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

2. Verifica si el paquete ya está instalado (`uv tool list` y busca `graphifyy`).
   Si ya está, no lo reinstales, pasa al punto 3. Si no está, instálalo con:
   uv tool install graphifyy
   (el paquete real en PyPI se llama "graphifyy", con doble "y" — la herramienta
   se llama Graphify, con una sola "y", no lo confundas al escribir el comando).

3. Verifica si el skill de Claude Code ya está instalado en `~/.claude/skills/`.
   Si ya está, no lo reinstales. Si no está, corre:
   graphify install --platform claude

4. Genera el grafo de este proyecto ejecutando la skill `/graphify .` (extracción
   completa: incluye código y archivos Markdown/documentos) y confírmame cuántos
   nodos y comunidades detectó. Solo si el proyecto tiene únicamente código,
   `graphify update .` alcanza.

5. Configura este proyecto para usar el grafo: agrega a mi CLAUDE.md de este
   proyecto (créalo en la raíz si no existe) la sección
   "KNOWLEDGE GRAPH NAVIGATION (GRAPHIFY)" con la regla de correr
   `graphify query "<pregunta>"` antes de grep/lectura cruda cuando
   `graphify-out/graph.json` exista, `graphify path "<A>" "<B>"` para relaciones,
   `graphify explain "<concepto>"` para conceptos puntuales. Para mantener el grafo
   al día: `graphify update .` solo cubre código y NO lee archivos .md; para Markdown
   usar `/graphify . --update` (incremental, gasta tokens de tu plan). Antes de
   consultar el grafo, comprobar si hay archivos más nuevos que
   `graphify-out/graph.json` con:
   find . -newer graphify-out/graph.json -type f \( -name '*.md' -o -name '*.ts' -o -name '*.js' \) -not -path './graphify-out/*' -not -path '*/node_modules/*' -not -path './.git/*' | head -1
   y si devuelve algo, correr `/graphify . --update` primero.

No toques ninguna otra dependencia de Python del sistema — todo debe quedar
aislado vía `uv tool install`. Al terminar, dame un resumen corto de qué se
instaló, qué ya estaba instalado y se saltó, y qué quedó configurado en este
proyecto.

## PROTOCOLO DE OUTPUT — modo Surgeon
- Zero filler: sin saludos, sin "claro que sí", sin conclusiones. Directo al código.
- Solo bloques modificados. Nunca reescribir archivos completos salvo pedido explícito.
- Colapsar código no tocado con: // ... existing code ...
- Máx 1–2 bullets al final del bloque — solo qué cambió.
- Máx 5 bullets en respuestas explicativas, salvo que se pida detalle.
- Confirmar destructivos [Y/N] antes de rm, resets de estado, builds de producción.
- Si se pega un error: diagnosticar directo del stack trace, sin preguntar qué se hizo antes.
- Ser directo. Cuestionar las malas ideas antes de ejecutarlas.
- Código listo para producción — sin placeholders ni TODO.
- Si algo no está claro, preguntar antes de asumir.

## COMANDOS ACTIVOS

| Comando | Efecto |
|---|---|
| /surgeon | Activa el protocolo de output Surgeon de arriba en cualquier punto de la sesión. |
| /surgeon off | Desactiva el protocolo, vuelve a comportamiento normal. |
| /save | Revisa cambios, agrupa por tipo, hace commits automáticos con nomenclatura estricta, refresca el grafo y genera el handoff. |
| /cierre | Refresca el grafo, genera log-sesion.md con el snapshot de la sesión y genera el handoff. Se llama /cierre porque /compact ya es un comando nativo de Claude Code. |

### Protocolo de Ejecución para /save
Cuando ejecute /save (o pida un commit), debo:
1. Correr git status y git diff para ver qué cambió.
2. Agrupar los cambios de forma lógica — si hay diseño y lógica juntos, separar en
   commits independientes.
3. Clasificar de forma estricta:
   - CSS/Tailwind/estilos sin cambiar lógica → style: ...
   - Nuevos componentes/rutas → feat: ...
   - Solución de bugs/errores → fix: ...
   - Limpieza de código/refactors → refactor: ...
   - Cambios en notas/Markdown → docs: ...
4. Ejecutar git add y git commit -m "[tipo]: [descripción corta en minúsculas y español]".
5. Refrescar el grafo (si el proyecto usa Graphify). Primero comprobar si hay archivos
   nuevos desde la última actualización:
   find . -newer graphify-out/graph.json -type f \( -name '*.md' -o -name '*.ts' -o -name '*.js' \) -not -path './graphify-out/*' -not -path '*/node_modules/*' -not -path './.git/*' | head -1
   Si devuelve algo, correr /graphify . --update (incremental: solo re-extrae lo que
   cambió, incluye archivos Markdown y gasta tokens de tu plan). Si no devuelve nada,
   omitir este paso. Ojo: graphify update . solo cubre código y NO lee archivos .md.
   (Sin el comando find, comparar la fecha de modificación de tus archivos con la de
   graphify-out/graph.json.)
6. Imprimir un resumen ultra corto de los commits realizados.
7. Generar el bloque de handoff exacto:

CONTINUAR:
- Proyecto: [nombre carpeta/proyecto activo]
- Último commit: [tipo: descripción corta]
- SDD activo: [/sdd/{feature}/ si aplica, o "N/A"]
- Próximo paso: [acción concreta inmediata]
- Bloqueadores: [Ninguno / listar]

Sin prosa extra en ese bloque, solo los 5 campos con valores reales. Inmediatamente
después, en línea aparte (fuera del bloque):

usa graphify para contexto — [contexto/proyecto activo]

### Estructura para /cierre (log-sesion.md)
Al ejecutar /cierre, primero refrescar el grafo (mismo chequeo del paso 5 de /save) y
después crear log-sesion.md en la raíz con este formato exacto:

# SESSION CONTEXT: [PROYECTO O HITOS DE HOY]
**Fecha:** [AAAA-MM-DD] | **Proyecto:** [nombre]

## 1. Lo que se hizo (Logros Técnicos)
* [viñeta de lo resuelto/implementado]

## 2. Estado Actual (State Snapshot)
* **Bloqueadores:** [Ninguno / listar]
* **Pendiente Inmediato:** [próximo paso crítico]

## 3. Puntos de Conexión Semántica (Para Graphify)
* [relaciones relevantes con otras partes del proyecto/negocio]

Al terminar de escribir log-sesion.md, generar el mismo bloque de handoff CONTINUAR:
descrito arriba (con "N/A" en Último commit si no hubo commits en la sesión), seguido
de la línea fija "usa graphify para contexto — [contexto/proyecto activo]".

No agregues nada más al CLAUDE.md fuera de estas secciones.

Antes de correr los prompts

¿Cuál de los dos prompts de CLAUDE.md uso?

Si ya usas Git, el 02, que hace commits reales. Si no sabes qué es un commit o no quieres arriesgarte a tocar Git, el 03 (SAFE), que nunca toca Git.

¿Instalar Graphify rompe mi Python?

No. Se instala con uv tool install, que crea un entorno aislado para el paquete. Nunca toca tu Python global ni las librerías de otros proyectos.

¿El paquete se llama «Graphify» o «graphifyy»?

La herramienta es Graphify, con una sola «y». El paquete en PyPI se llama graphifyy, con doble «y», porque el nombre corto ya estaba tomado. Usa ese nombre exacto al instalar.

¿Es cierto que CLAUDE.md no consume tokens?

No. Sí entra al contexto como cualquier texto de sistema. Lo real es que se carga solo, sin invocarlo, y con el caché de prompt su costo entre mensajes de la misma sesión es casi insignificante.
